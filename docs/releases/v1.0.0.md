# tdt-media-stream v1.0.0

首次发布 tdt-media-stream，新增 H.264 / H.265 编码视频 WebSocket 输出。发布端继续使用 RTSP，WS、WebRTC、HLS 和 RTSP 观看端共享同一路径及输入。

## 主要功能

- WS 视频出口复用读取鉴权、多人共享、按需源和 `runOnRead` / `runOnUnread`，WS reader 类型为 `wsSession`。
- 输出 CodecInfo、VideoFrame 和 EOS 二进制消息，保留 90 kHz PTS 与 B 帧重排关系。
- WS 不限制 Origin，原有读取权限继续生效。
- 提供中文对接文档、地址生成与消息解析示例、浏览器 WebCodecs 播放页。
- 提供 Linux、Windows、macOS 程序和 Linux AMD64 / ARM64 Docker 镜像。

## Docker 部署

```text
ghcr.io/zqhhh77/tdt-media-stream:1.0.0
ghcr.io/zqhhh77/tdt-media-stream:latest
```

镜像默认启用 WS，保留 `mediamtx.yml` 配置文件和 `MTX_` 环境变量。镜像包含 shell 和 CA 证书，供现有回调命令与 HTTPS 依赖使用；回调脚本及其额外依赖由部署方提供。

下载本版本附件中的 `docker-compose.yml` 与 `mediamtx.yml`，放在同一目录后执行：

```bash
docker compose up -d
```

默认配置允许匿名发布和读取，可通过 `authInternalUsers` 调整。示例 Compose 使用 RTSP over TCP；WebRTC 跨网访问仍需配置实际可达的 ICE 地址。

```text
RTSP 推流：rtsp://服务器地址:8554/camera/001
WS 观看： ws://服务器地址:8894/camera/001
```

如需离线导入，下载附件中的 AMD64 镜像包后执行：

```bash
docker load -i tdt-media-stream_v1.0.0_docker_amd64.tar.gz
```

导入后可使用相同的 Compose 配置。GHCR 包的可见性及仓库权限决定直接拉取是否需要登录；离线镜像包无需登录镜像仓库。

## 验证与边界

发布流程运行关联包及现有输出服务的竞态回归，并对实际 Docker 容器执行版本、WS 启动和 RTSP 输入 → WS 输出 → 浏览器 / FFmpeg 解码检查；全部通过后推送镜像并发布 Release。

WS 当前只输出视频，不包含音频；服务端不转码。H.265 的浏览器显示取决于目标浏览器的解码支持，不能将 FFmpeg 解码通过等同于浏览器支持。真实摄像机、现场网络和长时间播放仍需部署验收。
